# 구현 시작 게이트

상태: 구속력 있는 프로젝트 결정.

공통 해석기 계획 문서가 완성되었다는 이유만으로 구현, 마이그레이션, 제품 코드 변경을 시작하지 않는다.

구현을 시작하기 전에 Wingman은 반드시 다음을 수행한다.

1. 지금까지 쌓인 제품 계약, 명령 계약, 구조, 데이터 모델, 입력 판정, lexer 계약,
   공통 경로·파일 시스템 계약, 터미널 제출·세션 계약, 텍스트 record·stream 계약,
   mutation 실행 계약, CLI 실행 계약, prototype·target 경계, 보안 모델, 성능 예산,
   유지보수 계획, 테스트 계획을 하나의 일관된 제안으로
   재검토한다.
2. 그 검토에서 모순, 빠진 명령 동작, 안전 공백, 마이그레이션 위험을 찾는다.
3. 통합 구현 계획을 사용자에게 제시한다.
4. 구현 시작에 대한 사용자의 명시적 승인을 받는다.

4단계 전까지 문서화와 읽기 전용 리서치는 가능하다. 구현 코드, 호환성 리팩터링, 동작을 바꾸는 테스트는 하지 않는다.

현재 검토 결과와 구현 전 필수 수정은 [전체 계획 통합 재검토](CONSOLIDATED_PLAN_REVIEW.ko.md)에 정리한다.
