# `rm` 명령 계약 (P0)

상태: MVP 확정 범위입니다.

영문 원본: [RM.md](RM.md)

모든 target·root·상위 관계·identity·reparse 검사는 공통
[Windows 경로 계약](../WINDOWS_PATH_CONTRACT.ko.md)을 따른다.
요청 전체 사전 검증, 순회 순서, 부분 삭제, 취소는 공통
[mutation 실행 계약](../MUTATION_EXECUTION_CONTRACT.ko.md)을 따른다.

## 지원 문법

```text
rm [OPTIONS] PATH...
```

| 옵션 | 의미 |
| --- | --- |
| `-r`, `-R`, `--recursive` | 폴더와 그 안의 내용을 재귀 삭제 |
| `-f`, `--force` | 없는 경로를 무시하고 읽기 전용·숨김 항목도 삭제 시도 |
| `--` | 이후 인자를 옵션으로 해석하지 않음 |

짧은 옵션은 묶어서 쓸 수 있습니다. `rm FILE`은 파일만 삭제하고, 폴더에는
`-r`, `-R`, `--recursive` 중 하나가 필요합니다. 파이프 입력은 받지 않습니다.

삭제는 영구적이며 Windows 휴지통을 사용하지 않습니다. `-f`도 Windows ACL을
무시하거나 다른 프로세스가 열어 둔 파일을 삭제하지는 못합니다.

## 필수 안전 규칙

모든 대상은 wildcard가 없는 명시적인 경로여야 합니다. `*`, `?`는 거부하며,
`--no-preserve-root`를 포함한 지원하지 않는 옵션도 거부합니다.

재귀 삭제에서는 아래로 정규화되는 모든 대상을 거부해야 합니다.

- `C:\`, `C:/` 같은 Windows 드라이브 루트
- `\\server\share\` 같은 UNC 공유 루트
- 현재 작업 폴더
- 현재 작업 폴더의 상위 폴더

정규화 뒤에도 같은 보호를 적용하므로 `.`과 `..`로 우회할 수 없습니다. 명시한
대상이 symbolic link, junction, 그 밖의 reparse point라면 링크 자체만 삭제하고
대상 폴더를 재귀적으로 따라가지 않습니다.

첫 삭제 전에 모든 대상과 모든 재귀 tree가 전체 사전 검증을 통과해야 합니다.
알려진 안전 위반 하나라도 있으면 아무것도 삭제하지 않고 `2`, 필요한 identity·상위
관계·reparse 안전성을 확정할 수 없으면 아무것도 삭제하지 않고 `1`입니다.

## 종료 코드 규칙

재귀 삭제 사전 검증은 대상 root마다 항목 100,000개와 최대 깊이 256으로 제한합니다.
어느 한도를 초과해도 아무것도 삭제하지 않는 resource 안전 거부이며 종료 코드 `2`입니다.

- 요청한 모든 대상이 성공적으로 삭제되어야 종료 코드 `0`입니다.
- `-f` 없이 경로가 없거나 접근이 거부되거나 파일이 사용 중이면 `1`입니다.
- `-f`에서는 없는 경로만 성공으로 봅니다. ACL·사용 중 파일 오류는 여전히
  `1`입니다.
- 잘못된 문법, 대상 없음, 지원하지 않는 옵션, wildcard 경로, 안전 규칙 위반은
  `2`입니다.
- 전체 사전 검증 뒤 최상위 대상은 왼쪽부터 처리하고 재귀 tree는 공통의 결정적
  순서로 자식부터 부모 순서로 삭제합니다. 일반 실행 실패는 부분 삭제를 남길 수
  있고 안전 상태가 유효한 동안 이후 독립 대상은 계속 처리할 수 있습니다. 안전
  재검사가 달라지면 이후 삭제를 중단합니다. 이 경우 최종 상태는 `1`입니다.
- 취소는 `130`이며 이미 끝난 삭제를 되돌리지 않습니다.

## 의도적으로 지원하지 않는 문법

```text
rm -i file.txt
rm -I dir
rm -d empty-dir
rm -v file.txt
rm --one-file-system dir
rm --no-preserve-root /
rm *.log
find . | rm
```

## 필수 확인 예시

```text
rm notes.txt
rm -r temp
rm -rf dist cache
rm -- -file.txt
```
